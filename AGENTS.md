# AGENTS.md

Guidance for coding agents (and people) working in this repository. `CLAUDE.md` imports this file, so Claude Code and
other agents read the same rules.

PdfPecker.Rust is the `pdfpecker` crate on crates.io: the [PdfPecker](https://github.com/Moonwalker1307/PdfPecker)
.NET library, compiled with NativeAOT into a shared library with a C ABI, and a safe Rust API over it. The native
library is not built here: it is the one inside the wheels of
[PdfPecker.Python](https://github.com/Moonwalker1307/PdfPecker.Python) on PyPI, which builds it from the released
PdfPecker NuGet package. The crate's build script downloads the target's wheel, checks it and takes the library out;
the crate loads it at run time.

## Core rules

- **The libraries come from PyPI.** `wheels.txt` lists, for each of the eight platforms, the wheel URL and the SHA-256
  of the wheel and of the library inside it; `build.rs` refuses anything that does not match. `wheels.txt` is written
  by `scripts/update-wheels.py`, never by hand. Never build, copy or commit a native library here; when the crate needs
  something the library cannot do, fix PdfPecker (or the C ABI in PdfPecker.Python) in its own repository first.
- **The version is the library version.** `version` in `Cargo.toml` is the PdfPecker and pdfpecker (PyPI) version the
  crate holds; `library_version()` must return it, which a test checks.
- **No runtime dependencies.** The library is loaded with dlopen or LoadLibraryExW declared in `src/native.rs`, and
  JSON is written and read by `src/json.rs`. The build script may use pure-Rust crates (`sha2`, `miniz_oxide`), and
  downloads with the system's `curl` or `wget` so that no TLS stack is compiled.
- **The C ABI is PdfPecker.Python's.** `pdfpecker_invoke(op, input, input_len, options_json, &output, &output_len,
  &error)`, `pdfpecker_free`, `pdfpecker_version` and `pdfpecker_abi_version` (`native/Exports.cs` there). Options
  reach the native side under the Python keyword names, written by the `to_json` methods in `src/options.rs`. A new
  ABI version there needs `ABI_VERSION` in `src/native.rs` bumped in the same release.
- **Options grow without breaking.** Option structs have private fields and chained setters, and public enums are
  `#[non_exhaustive]`, so a release can add options and variants. No breaking API changes before 2.0.
- **Never unload the library.** The .NET runtime registers a destructor for each thread that called into it.
- **Never name a user's private application or employer** in code, tests, commits, the README or PR descriptions.

## Repo map

- `src/lib.rs` – the public functions and `PdfAResult`; `src/options.rs` – the option types and their JSON;
  `src/error.rs` – `Error` and `ErrorKind`, one kind per native status; `src/native.rs` – finding, loading and calling
  the library, and the list framing; `src/json.rs` – the JSON writer and the PDF/A report reader.
- `build.rs` – picks the target's wheel from `wheels.txt`, downloads or reuses the cached library, checks both
  hashes and copies the library into `OUT_DIR`; `PDFPECKER_LIB_DIR` skips the download, `DOCS_RS` skips everything.
- `wheels.txt` – generated by `scripts/update-wheels.py` from PyPI.
- `tests/api.rs` – the API against the real library; `examples/html_to_pdf.rs` – a small command line.
- `ci/test.sh` – fmt, clippy, tests and docs, then the packaged crate used as a dependency of a fresh project.
- `.github/workflows/ci.yml` – the eight platforms and Rust 1.85 on every PR, and the crates.io publish on a published
  release.
- `.github/workflows/vulnerability-scan.yml` – daily: OSV-Scanner on the build dependencies (results in Security → Code
  scanning), and an issue for each new .NET security release, since the library from the wheels carries the runtime.

## Wisdom

- A statically linked musl binary cannot dlopen, and Rust's musl targets link statically by default, so `build.rs`
  stops such a build with the `-C target-feature=-crt-static` advice instead of failing at run time.
- The 1.23.0 library reports a timeout above 2^31 - 1 milliseconds as an internal error, so `src/options.rs` checks
  the range first.
- crates.io allows 10 MB per crate and the library is about 19 MB, which is why the build script downloads it.
- The deep-nesting hostile-input test runs on a thread with Rust's default 2 MiB stack, which is enough for PdfPecker.

## Releasing

After a PdfPecker release reaches PyPI, a PR changes `version` in `Cargo.toml`, runs `scripts/update-wheels.py` and
adds functions or options for what the release added. The owner publishes the GitHub release `v<version>`; the
workflow publishes with the `CARGO_REGISTRY_TOKEN` secret or, once it is set up, Trusted Publishing (workflow
`ci.yml`, environment `crates-io`). Never publish, tag or create a release yourself.

## Commit guidance

- Branch from the latest `origin/main`, one branch per piece of work, named after the work with a `claude/` prefix
  when an agent creates it. Never reuse a branch name after its PR is merged or closed.
- Commit subjects are short imperative or descriptive sentences without prefixes; the body explains why.
- Fill in `.github/pull_request_template.md`, and update `README.md` in the same PR when a function or option changes.
